    Comparable and the natural order¶

    ☕ Java 17 · Teaching Java How to Order Your Objects · 1/4

    Every sort needs an order. Java already knows some of them, and you write the others.

    The orders Java already knows¶

    • Numbers sort from the smallest to the largest.
    • Strings follow the Unicode table: digits come before uppercase letters, and uppercase letters come before lowercase letters.
    import java.util.*;

public class StringOrder {
    public static void main(String[] args) {
        List<String> titles = new ArrayList<>(List.of("arcane", "Up", "24", "Arcane"));
        Collections.sort(titles);
        System.out.println(titles);
    }
}

    [24, Arcane, Up, arcane]

    That is why Up sorts before arcane. Collections.sort() returns void: it sorts the list you pass to it.

    Comparable: the order inside the class¶

    For your own classes, implement Comparable<T>. It has a single method, compareTo(). Thanks to the generic type, compareTo() receives a Movie, with no cast. Here it compares the titles, delegating to the compareTo() method that String already has.

    import java.util.*;

public class Movie implements Comparable<Movie> {
    private String title;
    public Movie(String title) { this.title = title; }
    public int compareTo(Movie m) { return title.compareTo(m.title); }
    public String toString() { return title; }

    public static void main(String[] args) {
        List<Movie> movies = new ArrayList<>(List.of(new Movie("Up"), new Movie("Dune"), new Movie("Coco")));
        Collections.sort(movies);
        System.out.println(movies);
    }
}

    [Coco, Dune, Up]

    A class has only one compareTo(), so it has only one natural order.

    What compareTo() returns¶

    Only the sign of the int matters:

    Result of a.compareTo(b) Meaning
    negative a comes first
    zero equal for sorting
    positive a comes after b

    For numbers, rating - other.rating sorts in ascending order and other.rating - rating in descending order. Integer.compare(rating, other.rating) does the same as the first one, safely.

    Older code may implement the raw type Comparable, without generics. The parameter is then an Object, and compareTo(Object o) must cast it (Movie m = (Movie) o;) before reading its fields. If the data may contain null, decide on purpose: throw an exception, or put null first.

    When compareTo() and equals() disagree¶

    A natural order is consistent with equals when compareTo() returns 0 exactly when equals() returns true. When it isn't, sorted collections behave in surprising ways:

    import java.util.*;

public class Inconsistent {
    record Title(int id, String name) implements Comparable<Title> {
        public int compareTo(Title t) { return name.compareTo(t.name); }
    }

    public static void main(String[] args) {
        Set<Title> set = new TreeSet<>();
        set.add(new Title(1, "Heat"));
        set.add(new Title(2, "Heat"));
        System.out.println(set.size() + " " + new Title(1, "Heat").equals(new Title(2, "Heat")));
    }
}

    1 false

    The two titles are not equal, but compareTo() returns 0. A TreeSet trusts compareTo(), treats the second one as a duplicate and drops it. Keep the two methods consistent, or sort with a Comparator instead.
